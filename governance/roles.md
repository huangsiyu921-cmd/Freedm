# 角色、权限与利益冲突

> 角色是**权限边界**，不是头衔。一个人可以兼任，但任一子系统上不得同时担任“作者”和“独立验证者”。
> 人员姓名由项目负责人填写并签署；未填写的角色视为未任命，相关门禁不得通过。

---

## 1. 角色定义

| 角色 ID | 名称 | 可以接触 | 明确禁止 |
|---|---|---|---|
| `ROLE-DIRTY` | 分析组（Dirty Team） | 目标 APK、反编译产物、动态抓包、真机/模拟器；**仅** Dirty 工作区 | 编写任何实现代码；读取 Clean 仓库源码/设计文档/测试结果；与实现组直接交流；在候选规格中保留代码、类名、资源名、独特界面细节 |
| `ROLE-COUNSEL` | 法律审查员 | 候选规格、Dirty 证据、必要的目标材料 | 参与实现；向实现组口述被剔除的原始表达；在未留书面记录时口头批准 |
| `ROLE-CLEAN` | 实现组（Clean Team） | **仅** 经法律审查的规格包、自己的代码与设计文档 | 接触目标 APK/反编译产物/动态证据；访问 Dirty 工作区；向分析组描述实现细节 |
| `ROLE-AUDIT` | 验证/审计组 | 流程证据、规格、构建产物；经批准可查看两侧 | 修改实现代码或规格正文；在担任某子系统作者时验证该子系统；把实现源码/设计文档交给盲测评审者 |
| `ROLE-REVIEW` | 独立验证评审者（按子系统临时任命） | 规格 + 黑盒构建产物 + 验收步骤 | 是该作者；阅读对应实现文档或源码；与作者讨论实现细节后再判定 |
| `ROLE-OWNER` | 项目负责人 | 全部治理记录 | 代替法律审查员签字；在关键门禁未通过时批准发布 |

### 1.1 角色隔离的最小实现

- `ROLE-DIRTY` 与 `ROLE-CLEAN` 使用不同的操作系统账户或至少不同的受控目录；共享账户只能作为**流程隔离**，必须在 `evidence.md` 中登记为补偿控制。
- `ROLE-CLEAN` 的工作区不得出现目标 APK、DEX、反编译源码、原始资源、抓包文件。
- `ROLE-DIRTY` 的工作区不得出现 Clean 的源码、设计文档、验收输出、日志。
- `ROLE-REVIEW` 只接收“盲测包”：规格 + 安装包 + 验收命令；不接收源码、设计文档、提交说明。

## 2. RACI

`R` 执行，`A` 最终负责，`C` 被咨询，`I` 被告知。

| 活动 | DIRTY | COUNSEL | CLEAN | AUDIT | OWNER |
|---|---|---|---|---|---|
| 目标获取与取证 | R/A | I | — | I | I |
| 黑盒观察/静态分析 | R/A | — | — | I | I |
| 候选规格编写 | R/A | C | — | C | I |
| 受保护表达剔除 | C | R/A | — | C | I |
| 规格批准 | — | R/A | I | C | I |
| 实现与设计文档 | — | — | R/A | I | I |
| 缺口登记与处置 | C | C | R | A | I |
| 独立验证 | — | — | C | R/A | I |
| 发布批准 | — | C | I | C | R/A |

> 关键点：`COUNSEL` 对“规格是否可以交付”拥有 A；`AUDIT` 对“验证结论是否有效”拥有 A；`OWNER` 对“是否发布”拥有 A。三者不可由同一人同时担任。

## 3. 利益冲突与独立性声明

每个角色在进入项目时签署：

```
姓名：
角色 ID：
日期：
我声明：
[ ] 我没有参与目标软件的原开发/反编译分包；
[ ] 我在本项目中不同时担任该子系统的作者与验证者；
[ ] 我未向另一组传递本角色无权传递的信息；
[ ] 我已知悉并遵守 information-flow.md 的单向规则；
[ ] 如发生利益冲突，我将立即书面报告。
签名：
```

声明存放：`governance/registry/role-declarations/`（不进入公开仓库）。

## 5. 交流禁令与例外

- **禁止** Dirty ↔ Clean 的任何直接交流（口头、IM、邮件、共享文档、代码注释、提交信息）。
- 唯一合法通道：`governance/handoff/`。Dirty 只能投递 `candidate/`；COUNSEL 只能投递 `approved/`；Clean 只能读取 `approved/`。
- 例外：`ROLE-AUDIT` 可以分别询问两侧，但不得把一方的受限信息转述给另一方；询问记录写入 `governance/audit/`。
- 违反一次的处置：停止相关门禁、登记 `INC-*`、评估受影响规格/代码范围；在纠正措施完成前不得发布。
