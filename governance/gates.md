# 阶段门禁（G0–G6）

> 门禁是“证据检查点”，不是会议。每个门禁必须有：准入条件、准出条件、证据、签署人。
> 未满足准出条件时，下一阶段只能以 `BLOCKED` 状态存在，不得“先做后补”。

---

## 总览

| 门禁 | 名称 | 主要执行者 | 关键产物 | 通过签署 |
|---|---|---|---|---|
| G0 | 立项与隔离 | OWNER + AUDIT | 角色任命、访问矩阵、工作区基线 | OWNER |
| G1 | 观察与取证 | DIRTY | 原始证据 + 哈希 + 观察记录 | DIRTY + AUDIT |
| G2 | 候选规格 | DIRTY | `CAND-*` + 稳定 ID + 自检表 | DIRTY |
| G3 | 法律审查 | COUNSEL | `LEG-*` + `approved/` 规格包 | COUNSEL |
| G4 | 实现 | CLEAN | 代码 + 设计文档 + 追溯矩阵 + 缺口 | CLEAN |
| G5 | 独立验证 | REVIEW + AUDIT | `REV-*` + 证据 + 结论 | REVIEW + AUDIT |
| G6 | 发布与关闭 | OWNER + AUDIT | 发布清单 + 缺口处置 + 证据归档 | OWNER |

---

## G0 · 立项与隔离

**准入**
- 项目范围、目标版本、目标平台、允许的观察方法已书面化。
- 已指定 OWNER、DIRTY、CLEAN、AUDIT 候选人；COUNSEL 已确定或明确标记缺失。

**准出（全部满足）**
- [ ] `roles.md` 人员登记完成，声明签署。
- [ ] 两个工作区的物理/账号边界已记录；共享账户补偿控制已登记。
- [ ] Clean 工作区基线扫描：无 APK/DEX/反编译源码/目标包名/原始资源。
- [ ] Dirty 工作区基线扫描：无 Clean 源码/设计文档/测试结果。
- [ ] 证据库位置、访问权限、保留期已确定。
- [ ] 本门禁的扫描输出归档为 `EV-*`。

**失败处理**：不得开始观察；先修复隔离或登记为 `BLOCKED`。

---

## G1 · 观察与取证（Dirty 专属）

**准入**
- G0 通过。
- 观察计划列明：设备/AVD、APK 版本与哈希、静态工具、动态 Hook 范围。
- 已确认不修改目标、不绕过授权、不采集与目的无关的个人数据。

**准出**
- [ ] 原始目标哈希、大小、来源、获取时间记录。
- [ ] 每条观察有 `OBS-*` 编号、方法、时间、设备/环境、原始输出路径。
- [ ] 动态证据含 Hook 脚本哈希与运行命令。
- [ ] 观察记录明确区分“观察到的行为”与“推断”。
- [ ] 未把任何 Clean 路径、实现命名、测试结果写入观察记录。
- [ ] 观察记录按 `D0`（原始证据）/`D1`（分析笔记）分类。

**失败处理**：证据不可复现或来源不明 → 标 `BLOCKED`，不得作为规格依据。

---

## G2 · 候选规格

**准入**
- G1 通过；观察记录可追溯到 `OBS-*`。
- 规格模板已就绪（ID、级别、行为、验证方法、来源）。

**准出**
- [ ] 每条需求/不变量/错误/验收有稳定 ID，且已在 `registry/ids.csv` 登记。
- [ ] 规定性条款与解释性说明分文件。
- [ ] 无源代码、伪代码、反编译类名/方法名/字段名/资源 ID/布局名。
- [ ] 无原始产品独特界面构图、配色、图标、逐字文案。
- [ ] 无 Clean 仓库路径、模块名、测试结果、性能数字。
- [ ] 每条条款可由第三方按描述验证；无法验证的标 `SHOULD` 或删除。
- [ ] 自检表 `information-flow.md §4` 全部勾选。

**失败处理**：退回 DIRTY；不得进入 G3。

---

## G3 · 法律审查

**准入**
- G2 通过；候选规格哈希已登记。
- COUNSEL 已任命且与两组无利益冲突。

**准出**
- [ ] 逐条审查记录：`KEEP` / `REDACT` / `REJECT`，附理由。
- [ ] 所有 `REDACT` 已落实到批准文本；所有 `REJECT` 条款不在批准包中。
- [ ] 批准包只含行为条款与 ID，不含原始表达。
- [ ] 批准包哈希、版本、生效日期记录。
- [ ] `LEG-*` 由 COUNSEL 签署；结论为 `APPROVED` 或 `APPROVED-WITH-REDACTIONS`。
- [ ] 若存在无法清除的相似表达，明确写入限制与后续动作。

**失败处理**：`REJECTED` 或未签署 → Clean 不得读取；已读取的按 `INC-*` 处理。

---

## G4 · 实现

**准入**
- G3 通过；`approved/` 只读包可用。
- CLEAN 已声明未接触目标材料。

**准出**
- [ ] 每个实现模块/提交标注对应的 `REQ-*`/`INV-*`/`ERR-*`。
- [ ] 设计文档标注 `INFORMATIVE`，不产生新约束。
- [ ] 构建可复现：工具链版本、命令、产物哈希。
- [ ] 规格与实现不一致全部登记 `GAP-*`，状态合法。
- [ ] 隐私基线 `PRV-*` 有静态检查结果。
- [ ] 未引入目标包名、原始类名、原始资源、原始文案。

**失败处理**：无法追溯的实现变更不得进入 G5。

---

## G5 · 独立验证

**准入**
- G4 通过；构建产物哈希固定。
- REVIEW 已任命；REVIEW 不是该作者，且未阅读实现文档/源码。
- 盲测包只含：批准规格、验收步骤、安装包、必要的数据文件。

**准出**
- [ ] 每条 `ACC-*` 有 PASS/FAIL/SKIP 与证据路径。
- [ ] 环境（设备/OS/网络/构建）记录完整。
- [ ] REVIEW 签署独立性声明：非作者、未读源码/设计文档。
- [ ] FAIL 项全部转为 `GAP-*`，并有处置状态。
- [ ] AUDIT 复核抽样证据，签署结论有效性。

**失败处理**：评审者独立性不成立 → 结论作废，重新任命。

---

## G6 · 发布与关闭

**准入**
- G5 通过。
- 所有 `GAP-*` 处于 `RESOLVED` / `ACCEPTED` / `DEFERRED`（有到期日）；无未处置的 `BLOCKED` 关键项。

**准出**
- [ ] 发布清单：版本、提交、构建哈希、签名指纹。
- [ ] 隐私基线 P1–P8 全部 PASS 或有书面豁免。
- [ ] 法律审查记录与批准包归档。
- [ ] 独立验证记录归档。
- [ ] 证据清单完整、哈希可校验、访问日志可审计。
- [ ] OWNER 签署发布决定；AUDIT 会签。

**失败处理**：不得发布；不得以“已知问题”代替缺口处置。
