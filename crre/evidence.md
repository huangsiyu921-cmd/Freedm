# 证据留存清单与保管链

> 原则：**没有证据的动作等于没发生**；证据必须可定位、可校验、可追责。
> 证据一旦入库只增不改；修订产生新 `EV-*`，旧证据保留。

---

## 1. 命名与元数据

```
EV-<阶段>-<序号>-<短名>
例：EV-G1-001-apk-hash、EV-G5-003-dl-resume
```

每条证据在 `crre/registry/evidence.csv` 登记：

| 字段 | 说明 |
|---|---|
| `evidence_id` | `EV-*`，永不复用 |
| `gate` | G0–G6 |
| `type` | hash / log / screenshot / report / build / review / legal / scan |
| `path` | 绝对或仓库相对路径 |
| `sha256` | 文件哈希；目录用归档后哈希 |
| `size` | 字节 |
| `created_at` | ISO-8601 带时区 |
| `owner` | 采集人 |
| `access` | `DIRTY` / `COUNSEL` / `CLEAN` / `AUDIT` / `PUBLIC` |
| `retention` | 保留至日期或事件 |
| `notes` | 来源、命令、环境 |

## 2. 按阶段的证据清单

### G0 立项与隔离
- [ ] 角色任命与独立性声明（`EV-G0-*`）
- [ ] 工作区基线扫描输出（Clean 无目标材料；Dirty 无实现材料）
- [ ] 访问矩阵与账号/主机说明
- [ ] 证据库位置与权限截图/配置

### G1 观察与取证
- [ ] 目标 APK：来源、版本、SHA-256、大小、获取时间
- [ ] 反编译产物清单与目录哈希
- [ ] 动态 Hook 脚本 + 运行命令 + 原始日志
- [ ] 网络抓包/端点扫描原始输出
- [ ] 截图/录屏（如使用）及其时间戳
- [ ] 观察记录 `OBS-*` 与原始输出的对应表

### G2 候选规格
- [ ] 候选规格全文哈希
- [ ] ID 注册表快照
- [ ] 自检表（无代码/命名/布局/实现引用）
- [ ] 条款到 `OBS-*` 的追溯表

### G3 法律审查
- [ ] `LEG-*` 审查记录（逐条 KEEP/REDACT/REJECT）
- [ ] 批准包全文哈希与版本
- [ ] 剔除内容清单（只记录类别与位置，不复制受保护表达）
- [ ] 审查员独立性声明

### G4 实现
- [ ] 构建命令、工具链版本、依赖锁文件
- [ ] 构建产物哈希与签名指纹
- [ ] 提交/变更到 `REQ-*` 的追溯矩阵
- [ ] 静态隐私检查输出（依赖、权限、设备标识、出网点）
- [ ] 缺口登记快照

### G5 独立验证
- [ ] 盲测包清单与哈希
- [ ] 每条 `ACC-*` 的结果与原始证据
- [ ] 测试环境（设备型号、OS、网络、构建）
- [ ] 评审者独立性声明
- [ ] 失败项的 `GAP-*` 链接

### G6 发布
- [ ] 发布清单（版本/提交/产物/签名）
- [ ] 缺口处置汇总（无未处置关键 `BLOCKED`）
- [ ] 证据库完整性报告（哈希校验）
- [ ] OWNER/AUDIT 签署

## 3. 保管链（Chain of Custody）

每次证据转移记录：

```
证据 ID | 从 | 到 | 时间 | 方式（复制/移动/只读挂载） | 哈希复核 | 签字
```

规则：
- 原始证据只读；分析在副本上进行。
- 跨区转移由 AUDIT 执行并记录；Dirty ↔ Clean 不直接转移。
- 证据库不放可执行文件；APK/DEX 只存放在 Dirty 受控区。
- 公开仓库只放不含目标材料的派生报告与治理文档。

---

## 4. 保留期

| 证据 | 最低保留 |
|---|---|
| 目标获取与哈希 | 项目结束后 3 年，或按法律要求更久 |
| 观察/动态日志 | 项目结束后 3 年 |
| 候选/批准规格 | 发布后 3 年 |
| 法律审查记录 | 发布后 5 年（或按法务要求） |
| 验证记录 | 发布后 3 年 |
| 发布产物与签名 | 与版本支持期一致 |

> 这是项目内控基线，不构成法律意见；如涉及诉讼保全，按法律顾问的保全通知执行。
